SQL Editor — Database Selection & Crash Handling

Shipped 5 commits make check green

The dropdown was a feature request. It uncovered a bug.

On MySQL and SQL Server the app never gave the connection a current database. Every other feature hid that by fully qualifying object names — the SQL editor is the one path that cannot.

1. Root cause — Error 1046 (3D000)

Service.session decided the connection's database from Caps().DatabasePerConnection, which is true for Postgres alone. Two different questions were being conflated:

  • DatabasePerConnection asks “does switching database require a new connection?” — Postgres: yes. MySQL and SQL Server: no.
  • What the session actually needed is “what should the current database be?” — always the one the user picked.

global4_laravel in the dropdown was genuinely selected — it just never reached the connection. The old header chip's comment claimed “the connection is already scoped to it, so use is never needed”, which had been false for MySQL and SQL Server the whole time.

2. The fix

Before
target := ""
if d.Caps().DatabasePerConnection {
    target = database
}
return s.engine.Acquire(
    ctx, connID, cfg, target)
After
return s.engine.Acquire(
    ctx, connID, cfg,
    sessionDatabase(database))

sessionDatabase is a named pass-through: it is where a dialect exception would go, and the regression test calls it, so re-adding a gate fails the build.

DialectBeforeAfter
postgresscopedscoped — unchanged
mysqlno databasescoped
mssqlno databasescoped
sqliten/aignores it — DSN is the file
Tradeoff. MySQL now gets one pool per database rather than one per server, as Postgres always had. Capped at 4 connections each with idle reaping after 5 minutes, so the cost is bounded — but the activity tray's session list will show more entries if you browse many databases. Cross-database queries are unaffected; the DSN database is only a default.

3. The dropdown

The old header showed a read-only chip, and only when a database was already chosen — so it went missing in exactly the case where you needed guidance. The picker is always rendered and adapts to what there is to choose. All decisions live in picker.ts, tested without a DOM.
